# Implementation plan, risks and status

This records the plan the suite was built against. Each step has a verification that was actually
executed. Status reflects version 0.1.

## Environment findings (before implementation)

- Empty repository; Python 3.13, Node 22, Chromium (Playwright build), Docker engine (daemon startable),
  root inside a container with `unshare(CLONE_NEWNET)` available; outbound HTTPS only through a
  TLS-intercepting proxy (custom CA); no model API keys available to the session.
- Consequences: Python as the implementation language (graders use pytest/Hypothesis, Playwright for
  browsers); local sandbox built on namespaces + privilege drop + rlimits, plus a Docker backend; the
  Docker image build accepts a CA as a BuildKit secret; **no real model could be evaluated in this
  environment**, so the pipeline is validated with deterministic scripted adapters and fake provider
  servers.

## Risks identified and how they were handled

| Risk | Handling |
|---|---|
| Benchmarks that any model passes (or none can) | Decoys designed before hidden tests; selftests encode expected score ranges; pass gates on core criteria so "do no harm" strategies cannot pass |
| Grader bugs mis-scoring models | Reference/no-op/decoy replays through the full pipeline; ground truth verified by execution where possible; grader exceptions are `error` status, not model failures |
| Flaky concurrency/performance verdicts | Deterministic interleavings, repeated stress counted as pass only if every repetition passes, join deadlines, CPU-time ratios; selftests re-run several times by the author |
| Contamination | Original scenarios, canary strings in hidden files, content hashes |
| Grader subversion by agents | Hidden tests injected only after the episode, isolated pytest invocation, tamper-file removal |
| Unsafe execution | Sandboxes, command policy, scrubbed env; Docker backend for untrusted systems |
| Unfair cross-provider comparisons | Applied/dropped params recorded; `system_kind`; comparability checks before ranking |
| Rubric subjectivity | Rubric criteria optional (provisional scores), evidence-required judges, self-judging blocked, human grading path |

## Not implemented (known gaps)

- No real-model results: no API credentials were available in the build environment.
- No calibration study of LLM-judge vs. human agreement for the rubrics.
- No parallel execution of attempts (`--jobs`); runs are sequential.
- No language other than Python in agent-mode fixtures (frontend uses HTML/CSS/JS; chat items include JS/SQL/git/HTTP facts).
- The frontend browser probe always runs on the local backend (the Docker image has no browser).
- No plotting beyond the inline SVG bars in HTML reports (e.g. no performance-vs-tier chart).
